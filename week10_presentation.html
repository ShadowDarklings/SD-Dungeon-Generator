The Elevator Pitch

What We Built

  • Procedural dungeon generator for Shadowdark RPG — an automated DM for solo tabletop play
  • Pick a level (1–10), generate a unique dungeon, explore under fog of war
  • Rooms, halls, doors, monsters, treasure, traps — all procedurally placed
  • Line-of-sight fog model — walls and doors block light
  • Save & load games with persistent state in Postgres
  • GitHub OAuth + password login, session hardening

🏰 Key Features

  • 46×31 tile grid with canvas rendering
  • Interactive tokens — defeat monsters, collect loot, trigger traps
  • Search rolls with modifier + tooltip breakdown
  • Loot log with running total
  • Character import from shadowdarklings.net
  • Full production stack: nginx → gunicorn → Flask → Postgres

Database Schema — 8 Tables

users
id · username · password_hash (nullable) · email · display_name
UserMixin · supports OAuth-only + password accounts
oauth_identities
user_id → users · provider · provider_user_id
UNIQUE(provider, provider_user_id)
saved_runs
user_id → users · seed · level CHECK 1–10 · state_json (JSON blob — source of truth for load) · created_at · updated_at
tiles
UNIQUE(run, x, y)
CASCADE delete
rooms
UNIQUE(run, key)
CASCADE delete
halls
UNIQUE(run, key)
CASCADE delete
entities
UNIQUE(run, key)

Architecture

Security — Defense in Depth

🛡️ nginx Layer

  • 20 attack paths → 404/403
  • Rate limiting: 5 r/m on auth endpoints
  • Strict-Transport-Security
  • X-Frame-Options: DENY
  • X-Content-Type-Options: nosniff
  • Content-Security-Policy
  • Referrer-Policy

🔒 Flask Layer

  • Flask-WTF CSRF on all forms
  • HttpOnly + SameSite=Lax cookies
  • SESSION_COOKIE_SECURE over HTTPS
  • Session lifetime: 2hr / 14d remember
  • ProxyFix for X-Forwarded-Proto
  • OWASP BOLA: 404 for not-owned runs
  • Secrets: os.environ["KEY"] — crash on missing

🗄️ Database Layer

  • No ports exposed to host
  • Docker-network-only access
  • CASCADE deletes on all child tables
  • Ownership isolation per user
  • UNIQUE constraints enforced
  • level CHECK 1–10
  • Parametrized queries (SQLModel)
nginx blocks scanners Flask enforces auth Postgres isolates data

Honest Reflection

What Worked, What Didn't

✅ What's Solid

  • Contract-first development — CONTRACTS.md drove tests, then code
  • Production stack runs end-to-end — docker compose up → HTTPS → working app
  • OAuth + session hardening + CSRF infrastructure all in place
  • 20 attack-path tests pass — nginx blocks scanner probes
  • Fog-of-war exploration is genuinely fun to play

⚠️ Held Together With Tape

  • CSRF enforcement disabled on form routes (@csrf.exempt) — tokens rendered but not validated
  • SQLite in tests vs Postgres in production — behavior gaps not exercised
  • No CI/CD deploy pipeline — only pytest CI exists
  • App connects as Postgres superuser, not least-privilege role
  • CSP may still break inline JS in the dungeon frontend

🔄 What We'd Do Differently

  • Start with the production stack earlier — not week 10
  • Build the deploy pipeline so CI → staging → prod is automated
  • Use an app factory pattern (create_app()) from the start
  • Email verification before OAuth auto-linking
  • Enforce CSRF from day one rather than adding exemptions to unblock
  • Run e2e tests against Postgres, not just SQLite
